# dsh-move · 搬家

把一台电脑上的 DSH 打包带走，在另一台上接着用。

带什么：会话、附件、技能、插件数据、长期记忆、人设、配置文件。
不带什么：`node_modules`、运行时、缓存、日志——那些在新机器上重装更干净。

## 怎么用

在旧电脑：

1. 设置 → 搬家
2. 确认清单没问题，选个保存位置，设一个密码
3. 点「打包带走」，等几分钟

在新电脑：

1. 先把这个插件装上（和旧电脑上用同一个包）
2. 设置 → 搬家 → 点「导入」，选 `搬家包.dshpack`，输密码

## 装到 DSH 里

这个插件不是从市场装的，是本地包。三步：

1. 把整个文件夹放到 `~/.dsh/profiles/desktop/node_modules/dsh-move`（Windows 上是 `C:\Users\<你>\.dsh\profiles\desktop\node_modules\dsh-move`）。
2. 打开同目录下的 `package.json`，找到 `dsh.profile.bundles`，在数组里加一行 `"dsh-move",`。
3. 重启 DSH。

设置里就会出现「搬家」。

如果你已经装过别的本地插件、`node_modules` 里那一堆是符号链接，那就建个目录链接指过来也行，效果一样：

```powershell
New-Item -ItemType Junction `
  -Path "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-move" `
  -Target "<你放源码的地方>\dsh-move"
```

## 包里长什么样

单文件 `.dshpack`，结构：

```
"DSHMOVE1\n"                 ← 魔数
[u32 头长度][JSON 头]        ← 明文，不加密也能看出这是谁的包
[16 字节 salt][12 字节 iv]   ← 有密码才有
[密文 …][16 字节 GCM tag]
```

正文（加密前）是 gzip 过的容器，一串 `[路径][大小][内容]`。

同目录另外三个文件：

- `清单.json` —— 包里每个文件的路径，出问题时靠它核对
- `搬家说明.html` / `.txt` —— 给人看的，讲怎么用

## 设计取舍

**白名单，不是黑名单。** 黑名单永远漏，今天新增一个缓存目录明天包里就多几百兆。白名单漏了顶多少带东西。

**压缩级别 1。** 包里大半是图片和已经压过的会话文件，高压缩级别只是白烧 CPU。

**密码做体检。** 包头里存一个 HMAC，解包前先比一下。不这么做的话，错密码会一路解出垃圾数据，报出来的错是「路径长得离谱」，跟密码完全对不上号。

**导出不碰原文件。** 只读打开会话文件，不锁、不改、不移动。打包中你还能继续用 DSH。

## 目前的边界

- 只做了导出。导入端还没写。
- 打包期间请尽量不要用 DSH——不是会坏，是怕读到写了一半的会话。
- Windows 优先。路径适配那套在别的系统上没验过。
