# dsh-move · 搬家

把一台电脑上的 DSH 打包带走，在另一台上接着用。

带什么：会话、附件、技能、插件数据、长期记忆、人设、配置文件。
不带什么：插件代码、`node_modules`、运行时、缓存、日志。前面那几样在新机器上重装更干净，后面那几样根本不用带。

## 怎么用

**旧电脑**

1. 设置 → 搬家
2. 确认清单没问题，选个保存位置，设一个密码
3. 点「打包带走」，等几分钟

**新电脑**

1. 先把这个插件装上（见下一节），和旧电脑上用同一份
2. 设置 → 搬家 →「或者，从另一台电脑搬过来」→ 选 `搬家包.dshpack` → 输密码
3. 跑完卡片里直接能看到这次的搬家说明；想细看就点「打开搬家说明」

## 装到 DSH 里

不是从市场装的，是本地包。三步：

1. 把整个文件夹放到 `~/.dsh/profiles/desktop/node_modules/dsh-move`（Windows 上是 `C:\Users\<你>\.dsh\profiles\desktop\node_modules\dsh-move`）。
2. 打开同目录下的 `package.json`，找到 `dsh.profile.bundles`，在数组里加一行 `"dsh-move",`。
3. 重启 DSH。设置里就会出现「搬家」。

如果你习惯留一份源码在别处，做目录链接也行，效果一样：

```powershell
New-Item -ItemType Junction `
  -Path "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-move" `
  -Target "<你放源码的地方>\dsh-move"
```

## 包里长什么样

单文件 `.dshpack`：

```
"DSHMOVE1\n"                 ← 魔数，9 字节
[u32 头长度][JSON 头]        ← 明文：时间、机器、文件总数、工作区、插件清单
[16 字节 salt][12 字节 iv]   ← 有密码才有
[密文 …][16 字节 GCM tag]
```

正文（加密前）是 gzip(level 1) 过的容器，一串 `[u32 路径长][路径][u64 文件长][内容]`。

加密是 PBKDF2-HMAC-SHA256（10 万次迭代）派 256 位密钥，AES-256-GCM。包头里存一个 HMAC 摘要，解包前先比——错密码当场报「密码不对」，不会解出一堆垃圾再说别的话。

同目录另外三个文件：

- `清单.json` —— 包里每个文件的路径，出问题时靠它核对
- `搬家说明.html` / `.txt` —— 给人看的，讲怎么用、包里有什么、哪三件事别做

## 搬的时候会发生什么

**冲突：搬来的赢。** 包里有的文件如果本地也有、内容不一样，包里的盖掉本地，本地那份改名成 `原名.bak-<时间戳>`，留在原目录。想退回去，把 `.bak-` 去掉就行。

**`package.json` 只加不减。** 这是唯一的例外——整体覆盖会把新机器上装过的插件全冲掉。所以只往里加包里多出来的 bundle 和依赖，本机原有的一条不动，同名依赖保留本机版本。

**工作区路径会跟着变。** 会话文件的第一帧里记着权威的 `cwd`，目录名只是它的编码。搬到新机器时逐个判：

| 情况 | 处理 |
|---|---|
| 目标目录已经在了 | 原样，一个字节不改 |
| 盘符在、目录不在 | 建出来 |
| 盘符都不存在 | 落到 `~/DSH搬家-工作区/<去掉盘符的原路径>` |

改的时候只换第一帧，后面几千帧原样拼回去——那些帧里凡是提到路径的地方，是你说过的话，不动。

**插件本体不在包里。** 包里只有插件数据。报告里会列出「这台机器上还缺这几个插件」，照着装一遍，数据自动接上。

## 设计取舍

**白名单，不是黑名单。** 黑名单永远漏：今天多一个缓存目录，明天包里就多几百兆。白名单漏了顶多少带东西，不会带进不该带的。

**压缩级别 1。** 包里大半是图片和已经压过的会话文件，高压缩级别只是白烧 CPU。345MB 扫完一秒，压完一分多钟。

**同时只跑一个任务。** 两个一起跑会互相抢盘，谁也快不了。

**导出不碰原文件。** 只读打开会话文件，不锁、不改、不移动。打包中你还能继续用 DSH。

**会话不是一个大压缩包，是几千个 zstd 帧首尾相接。** DSH 每写一批就往后面追加一块。所以按 magic 切段逐段解，不能用流式解压——流在第一帧末尾就报 `Unknown frame descriptor`。

## 边界

- 打包期间尽量别用 DSH。不是会坏，是怕读到写了一半的会话。
- 新建的会话如果在打包那一刻正在写，可能落在包里但不完整。宁可少一条，不搬半条。
- 任务记录只留最近 8 条，过了就只能在报告目录里找。
- Windows 优先。路径适配那套在别的系统上没验过。
